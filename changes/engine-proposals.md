Engine proposals: a missing engine part lives in `<feature>.engine.ts` next to the game, and `jgengine propose` turns it into the issue

### Added

- `defineEngineProposal`, `engineProposalProblems`, `ENGINE_PROPOSAL_KINDS` and the `EngineProposal` type (`@jgengine/core/meta/proposal`): the metadata a `<feature>.engine.ts` file exports (`id`, `target` public import path, `need`, `kind` `new`/`extend`/`fork`, `fork` engine file, `exports`). `defineEngineProposal` returns it unchanged and throws when it is invalid.
- `jgengine propose [dir]`: finds every `*.engine.ts` file (default the current folder; `games/` at the engine repository root) and prints a ready-to-file GitHub issue for each (title `Engine proposal: <id>`, the need, target, kind, exports, the full proposal files and, for a fork, a unified diff against the engine file it copies). It never calls GitHub. `--list` shows each proposal's status: `local`, `partial` or `upstream` (every name in `exports` resolves at `target`). `--check` fails on invalid metadata, an import that would not lift into the engine as-is (a game file, a path alias, a private `@jgengine/*/src` path), a TODO left in the metadata, an `upstream` proposal still in the game, and one id carried by two games. `--migrate <folder>` turns an `engine-local/<name>/` folder into proposal form: `<name>.engine.ts` (and `<name>.draw.engine.ts` for its draw files) with inferred metadata and TODO fields, and the game's imports moved onto it. `--id <id>` picks one proposal, `--json` prints machine output.
- `bun run check engine-proposals` runs `jgengine propose --check` over `games/`; `verify:fast` and CI's games job run it.
